# Правила роботи з музичними інструментами

## Обсяг і джерело

- Канонічна робоча папка: `C:/Users/User/Desktop/musical-instruments-site`.
- Перед задачею прочитати цей файл, `README.md` і потрібні записи `EVIDENCE.md`.
- Писати українською. Не вигадувати факти, дозволи, перевірки або причини дефектів.
- Статус: `Done`, якщо критерії виконано; `Partial`, якщо є незакритий обсяг; `Blocked`, якщо немає необхідного доступу чи дозволу.

## Контроль файлів

1. Перед змінами перевірити `git status --short`; зберегти попередні зміни власника.
2. Вказати мету, точні файли й критерії приймання. Не змінювати сторонній обсяг.
3. `dist/` містить релізний сайт; `standalone/` — окремі автономні варіанти. Вони можуть відрізнятися; синхронізацію не виконувати неявно.
4. Нові HTML, тести, документацію та референси включати до Git. Архіви залишати у `backups/` поза Git.
5. У задачах перенесення, дизайну чи документації не змінювати аудіорушії, тембр або гучність.
6. Перед commit показати перелік змін, `git status --short`, `git diff --name-only`; для індексованих файлів також `git diff --cached --name-only`.
7. Commit робити після виконання локального обсягу й відповідних перевірок. Push, PR і merge потребують окремого явного дозволу власника.
8. Не використовувати тимчасовий checkout як нове канонічне джерело. Після дозволеного релізу звірити робочу гілку, точний release commit і запис у `EVIDENCE.md`.

## Перевірки

- Для перенесення перевіряти хеші файлів, повноту історії, Git-стан і цілі посилань.
- Для коду запускати перевірки, що відповідають зміні. Емуляція телефона не доводить результат на фізичному пристрої.
- Не читати `.env`, ключі, токени, паролі, приватні журнали, DB або Redis. Наявність файла можна перевірити без читання значень.
- Наприкінці показати статус, файли, перевірки, незакриті питання, production/secrets, commit і `git status --short`.

## Публікація

GitHub-репозиторій і deployment Sites — окремі дії. Підготовка файлів не дозволяє push або deploy.

Перед production-дією прочитати `../founder-office/infrastructure/README.md`: це єдиний чинний реєстр Site та правил backup/rollback. Якщо він недоступний або необхідний пункт не підтверджений — статус `Blocked`, production не змінювати.

Deploy дозволений лише після перевірки точного commit, маршрутів і файлів, manifest, backup/restore, rollback, критеріїв зупинки та явного дозволу власника на підготовлений обсяг. До архіву сайту входять тільки погоджений `dist/` і потрібний hosting manifest; `.git`, документація, референси, тести та backups не публікуються як сайт.
