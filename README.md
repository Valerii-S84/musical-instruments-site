# Сайт музичних інструментів

Самостійний репозиторій сайту зі скрипкою, гітарою та віолончеллю. Канонічна робоча папка: `C:/Users/User/Desktop/musical-instruments-site`.

Усі зміни коду, тестів, документації та референсів мають відстежуватися в цьому Git. Релізний код — у `dist/`; тимчасові checkout не є робочим джерелом проєкту.

## Структура

- `dist/` — файли сайту: головна сторінка, `/studio/`, `/guitar/`, `/cello/` і зображення.
- `standalone/` — автономні HTML трьох інструментів; вони також відстежуються Git.
- `references/` — вихідні зображення та попередні знімки для роботи над дизайном.
- `backups/` — локальні архіви попередніх випусків. Вони не входять до `dist/` і не відстежуються Git.
- `tests/` — наявні регресійні перевірки віолончелі.
- `.openai/hosting.json` — конфігурація чинного статичного Site.
- `AGENTS.md` — правила роботи агентів; `EVIDENCE.md` — датовані записи перевірок.

## Перевірений реліз

Реліз від 2026-10-11: версія 5, source commit `fd1369d7bbde502382c5b9feb7d4a883a0fa8c7a`. Адреса: [сайт музичних інструментів](https://violin-cherry-velvet.svalerchik.chatgpt.site/). Код усіх трьох публічних інструментів звірено з цим commit через HTTPS GET; маршрути повернули 200. Перенесення репозиторію не змінює цей реліз.

На момент перенесення `dist/cello/index.html` і `standalone/Cello_Studio.html` побайтно однакові. Автономні гітара й скрипка відрізняються від сайтних HTML та їхніх скриптів; обидва варіанти збережено без синхронізації. Перед наступними змінами потрібно явно вибрати потрібний файл і перевірити, чи має змінюватися друга копія.

## Локальний запуск

Із цієї папки виконайте `python -m http.server 8000 --bind 127.0.0.1 --directory dist` і відкрийте `http://127.0.0.1:8000/`. Перевірте головну сторінку, `/studio/`, `/guitar/` та `/cello/`.

## Контроль змін і GitHub

Перед роботою перевірте `git status --short`. Перед commit перегляньте `git diff --name-only` і `git diff`; після індексації — `git diff --cached --name-only` і `git diff --cached`. Нові HTML, тести, документацію й референси потрібно додавати до Git, а не залишати лише у локальній папці.

Для GitHub підготовлено повну історію п'яти Site commits і поточні файли проєкту. Віддалений GitHub-репозиторій ще не створено й не підключено. Назва, власник, видимість і ліцензія потребують рішення власника перед публікацією. Не припускати, що для всіх ресурсів погоджено відкриту ліцензію.

`backups/`, архіви релізів, `.env`, ключі, локальні залежності й тимчасові результати виключені через `.gitignore`. Зміна Git remote або push на GitHub не публікує сайт: новий deploy Sites є окремою дією.

Правила production, реєстр Site, backup і повернення залишаються в [документі інфраструктури Founder Office](../founder-office/infrastructure/README.md). Перед deploy потрібні перевірений точний commit, backup, rollback і явний дозвіл власника на конкретний обсяг. GitHub push також потребує окремого дозволу.

## Віолончель — локальна сторінка

Відкрийте [Cello_Studio.html](standalone/Cello_Studio.html) у браузері. Це один автономний файл: зображення, звук, стилі й навчання працюють без мережі та встановлення пакетів. Сайтна копія — [dist/cello/index.html](dist/cello/index.html); головна сторінка відкриває цей маршрут у релізі 5.

- Великий робочий план грифа, чотирьох струн і смичка. У першій позиції кадрування вміщує всі чотири позначки пальців і зону смичка. На телефоні збережено портретну орієнтацію; на короткому екрані навчальні елементи доступні через вертикальне прокручування.
- «Смичок»: оберіть ноту й ведіть пальцем поперек струн або нижньої зони; зупинка руху гасить звук. Кнопка струни чи ↔ відтворює один штрих без перетягування. «Щипок» реагує на дотик та перетин кожної струни.
- «Відкриті» відкриває першу позицію; «Вчитися» містить чотири власні вправи, прослуховування та локальне збереження завершених вправ. Перевіряються ноти, а не точність ритму чи постановка руки.
- Q W E R — струни, 0–4 — пальці, пробіл — один штрих, Esc — тиша. Під час утримання клавіші кнопки пальців і струн змінюють звучну ноту; у щипку зміна ноти дає новий щипок. Повторна нота навчання потребує нового штриха, зміни напрямку смичка або повторного щипка. У налаштуваннях: гучність, темп, відтінок, вібрато та метроном.

Синтез звуку віолончелі власний; чужі записи для неї не використано. [Докази та джерела](EVIDENCE.md). Власник повідомив 2026-10-11, що звук на інших телефонах нормальний; моделі пристроїв і окремі результати Safari/iOS не надані.

## Перевірка віолончелі

Із цієї папки: `node --test .\tests\cello-regression.cjs`. Для тесту потрібні Node.js, `playwright-core` і встановлений Chromium. Сама HTML-сторінка цих залежностей не потребує.

Якщо засоби тесту встановлені окремо, задайте `PLAYWRIGHT_MODULE` як абсолютний шлях до модуля `playwright-core`, а `CELLO_CHROMIUM_PATH` — до виконуваного файла Chromium. `CELLO_QA_OUTPUT_DIR` може вказувати на тимчасову папку поза checkout для результатів і знімків. Не використовуйте особистий браузерний профіль; тест запускає окремий профіль із увімкненим sandbox Chromium.

Набір перевіряє дев’ять дефектів аудиту, стандартні й резервні діалоги, усі вправи, переривання, відновлення звуку, вісім розмірів екрана, шість сценаріїв поліфонії та однаковість HTML-копій. Це локальна перевірка Chromium; вона не підтверджує роботу на фізичному iPhone або натуральність тембру.
